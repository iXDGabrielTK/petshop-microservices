## 1. Contexto & Invariantes

- **Pré-condições Técnicas e Fronteira Afetada:**
  - `ConflictException` e seu `@ExceptionHandler` (`409 ProblemDetail`) já residem em `common-lib` desde o PR 3 (`E3`), incluindo os construtores `(String)` e `(String, Throwable)` que permitem preservar a causa na subclasse.
  - [`VendaController`](../../../apps/inv-service/src/main/java/inv/checkout/infrastructure/web/controller/VendaController.java#L110-L120) ainda declara dois `@ExceptionHandler` locais que respondem `{"mensagem": "..."}` para `CancelamentoVendaConflitoException` (`409`) e `CancelamentoVendaDesabilitadoException` (`503`), quebrando a uniformidade RFC 7807 do [`GlobalExceptionHandler`](../../../apps/common-lib/src/main/java/common/exception/GlobalExceptionHandler.java).
  - Nenhum outro microsserviço Java no workspace consome `/vendas/{id}/cancelar`; apenas clientes externos (SPA / PDV) leem o corpo de erro desse endpoint e devem ser coordenados antes do deploy.

- **F5 / Q5 — `ServiceUnavailableException` (`503 ProblemDetail`) em `common-lib`:**
  - **Invariante / Solução:** Adicionar `ServiceUnavailableException extends RuntimeException` em `common.exception` (espelhando `BusinessException`, `ResourceNotFoundException` e `ConflictException`) e registrar `@ExceptionHandler(ServiceUnavailableException.class)` no `GlobalExceptionHandler` retornando HTTP **503 Service Unavailable** com `ProblemDetail` (`title`, `detail`, `status`, `type`, `timestamp`).

- **Q5 — Unificação de Exceções em `inv.checkout.usecase` e Remoção dos Handlers Locais:**
  - **Invariante / Solução:** Alterar [`CancelamentoVendaConflitoException`](../../../apps/inv-service/src/main/java/inv/checkout/usecase/CancelamentoVendaConflitoException.java) para estender `common.exception.ConflictException` e [`CancelamentoVendaDesabilitadoException`](../../../apps/inv-service/src/main/java/inv/checkout/usecase/CancelamentoVendaDesabilitadoException.java) para estender `common.exception.ServiceUnavailableException`, preservando os três construtores (`()`, `(String)`, `(String, Throwable)`) e o fallback para `DEFAULT_MESSAGE` quando a mensagem recebida for `null`.
  - Remover integralmente os métodos `handleCancelamentoVendaConflito` e `handleCancelamentoVendaDesabilitado` de `VendaController`, delegando o tratamento ao `GlobalExceptionHandler` da `common-lib` sem alterar o módulo `inv.checkout.usecase` para os consumidores da regra de negócio.

- **Q5 — Atualização Coordenada de Testes e Documentação:**
  - Atualizar [`GlobalExceptionHandlerTest`](../../../apps/auth-service/src/test/java/common/exception/GlobalExceptionHandlerTest.java) (`auth-service`), [`VendaControllerTest`](../../../apps/inv-service/src/test/java/inv/checkout/infrastructure/web/controller/VendaControllerTest.java) (4 asserções de `409`/`503` migrando de `$.mensagem` para `ProblemDetail`) e [`CancelamentoVendaConcluidaIT`](../../../apps/inv-service/src/test/java/inv/it/CancelamentoVendaConcluidaIT.java#L333) (linhas 333, 360 e 481).
  - Atualizar [`apps/inv-service/README.md`](../../../apps/inv-service/README.md), [`docs/domains/checkout.md`](../../../docs/domains/checkout.md) e registrar nota evolutiva em [`docs/debt/DEBT-ARCH-003/E3.md`](../DEBT-ARCH-003/E3.md) indicando a migração do formato local para `ProblemDetail`.

### Exceções de Domínio/Aplicação e `GlobalExceptionHandler`

```java
// common.exception.ServiceUnavailableException (apps/common-lib)
@ResponseStatus(HttpStatus.SERVICE_UNAVAILABLE)
public class ServiceUnavailableException extends RuntimeException {
    public ServiceUnavailableException(String message) { super(message); }
    public ServiceUnavailableException(String message, Throwable cause) { super(message, cause); }
}

// GlobalExceptionHandler — @ExceptionHandler(ServiceUnavailableException.class)
// Retorna ResponseEntity<ProblemDetail> HTTP 503 (title: "Serviço Indisponível", type: "https://petshop.com/errors/service-unavailable")

// inv.checkout.usecase
public class CancelamentoVendaConflitoException extends ConflictException { ... }
public class CancelamentoVendaDesabilitadoException extends ServiceUnavailableException { ... }
```

### Critérios de Teste (Comportamento Esperado)

- **Cenário 1 — Handler global HTTP 503 (`GlobalExceptionHandlerTest`):**
  - *Condição:* Instância de `ServiceUnavailableException` com detalhe explícito.
  - *Ação/Gatilho:* Invocar o método handler `503` no `GlobalExceptionHandler`.
  - *Asserção/Resultado Esperado:* Retorna `ResponseEntity<ProblemDetail>` com status `503`, `title` não vazio, `detail` preservado, `type` terminando em `service-unavailable` e propriedade `timestamp`.
- **Cenário 2 — HTTP 409 e 503 em `ProblemDetail` sem handler local (`VendaControllerTest`):**
  - *Condição:* `VendaService.cancelarVendaConcluida` lança `CancelamentoVendaConflitoException` (com mensagem ou `null`) ou `CancelamentoVendaDesabilitadoException` (com mensagem ou `null`).
  - *Ação/Gatilho:* Executar `POST /vendas/{id}/cancelar` via `MockMvc` com `GlobalExceptionHandler`.
  - *Asserção/Resultado Esperado:* Resposta HTTP 409 / 503 com `$.detail` populado (sem `NPE` para `null`, usando `DEFAULT_MESSAGE`), `$.title`, `$.status` e `$.type`, e ausência de `$.mensagem`; os testes dos construtores preservam a mensagem/fallback e a identidade da causa, sem expor a causa interna no JSON.
- **Cenário 3 — Fluxo E2E em `CancelamentoVendaConcluidaIT` (`409` e `503`):**
  - *Condição:* Venda já `CANCELADA` (linha 333), feature flag `false` (linha 360) e venda em `AGUARDANDO_PAGAMENTO` (linha 481).
  - *Ação/Gatilho:* Executar `POST /vendas/{id}/cancelar` com PostgreSQL Testcontainers ativo.
  - *Asserção/Resultado Esperado:* HTTP 409 e 503 retornam `ProblemDetail` RFC 7807 com `$.detail` correspondente e `$.title` válido; todos os cenários do `*IT` executam e passam integralmente.
