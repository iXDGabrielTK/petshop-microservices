## Invariantes
- **Q1** — **Integração Checkout → Inventory: chamada síncrona in-process via Open Host Service em `inv.inventory.api`, com `Propagation.MANDATORY` na implementação.** O ACID vale **por operação**: a reserva (`iniciarVenda`) e a baixa (`VendaEventHandler`, via webhook → evento → RabbitMQ) são transações distintas. A consistência entre elas é garantida pelo modelo **reserva → baixa / estorno**, não por uma transação única.
  - **Impacto:** Sem consistência eventual na reserva do PDV. A resposta do `POST` de venda continua sendo "estoque reservado ou erro" na mesma transação. Nenhum evento novo é necessário. O teste `EstoqueCommandServiceIT.semTransacaoAtivaFalha` prova o `MANDATORY` (`IllegalTransactionStateException`).
- **Q2** — **Opção A, segregação comando/consulta:** `EstoqueCommandService` (reserva, baixa, estorno) e `CatalogoQueryService` (`ProdutoCheckoutView` com **apenas** `id`, `nome`, `precoVenda`; **sem** filtro de produto inativo). `EstoqueQueryService` (Dashboard) fica intacto.
  - **Impacto:** Simetria com `VendaQueryService`/`EstoqueQueryService` (R9/R10). A implementação de catálogo é package-private em `inv.inventory.infrastructure.query` (R10). A de comandos é o próprio `EstoqueService`, que vira package-private (R14 nova).
- **Q3** — **Operações em lote nos três comandos.** A implementação ordena os itens internamente por `produtoId` crescente (ordenação estável), **independente da ordem do chamador**, e executa **um `UPDATE` atômico por item**. **Proibido** usar `UPDATE ... FROM (VALUES ...)`: o PostgreSQL não garante a ordem de aquisição dos locks em um único statement com join.
  - **Impacto:** Ordem global de locks → sem ciclo de espera entre carrinhos (F5). As 3 queries atômicas de `ProdutoRepository` (ADR-0002) ficam **inalteradas**. Teste [`CarrinhosInvertidosDeadlockIT`](../../../apps/inv-service/src/test/java/inv/it/CarrinhosInvertidosDeadlockIT.java) + controle negativo (E4 — concluído).
- **Q9** — **Refatoração com paridade funcional.** Erro de indisponibilidade continua reportando **só o primeiro produto faltante**, com a **mensagem exata** atual (`"Estoque insuficiente para o produto: " + nome`). Sem consolidar itens duplicados e sem validar produto inativo. **Única exceção:** o guard de `CANCELADA` (Q10), em commit isolado red-green.
  - **Impacto:** **Nuance documentada:** com a ordenação da Q3, "primeiro faltante" passa a significar o primeiro **em ordem de `produtoId`**, não na ordem do request. Só faz diferença com **2+ produtos faltantes no mesmo carrinho**; o formato da mensagem é idêntico. **Correção colateral inevitável (F6):** o alerta anti-spam passa a usar a pré-imagem exata calculada sob o row lock, então deixa de disparar alertas duplicados sob concorrência (comportamento estritamente melhor; ver a seção 2.3 de [E2.md](./E2.md)).
- **F4** (🟠 Alta) — Checkout injeta `EstoqueService` (interno): esta etapa cria a porta pública `inv.inventory.api.EstoqueCommandService`; a migração do Checkout fica na E3 ([E3.md](./E3.md)).
- **F5** (🟠 Alta) — Risco de deadlock `40P01` em carrinhos multi-item iterados em ordem arbitrária (`[A, B]` vs `[B, A]`): resolvido aqui pela ordenação determinística por `produtoId` crescente nos 3 comandos em lote de `EstoqueService` (Q3) e provado na E4 ([E4.md](./E4.md) — concluído).
- **F6** (🟠 Alta) — `EstoqueService` depende da entidade `Produto` pré-carregada ([EstoqueService.java#L35](../../../apps/inv-service/src/main/java/inv/inventory/usecase/EstoqueService.java#L35), [#L44-L52](../../../apps/inv-service/src/main/java/inv/inventory/usecase/EstoqueService.java#L44-L52), [#L93-L105](../../../apps/inv-service/src/main/java/inv/inventory/usecase/EstoqueService.java#L93-L105)): resolvido conforme a tabela da seção 2.3 abaixo (`saldoAnterior = novoSaldo + qtd` sob o row lock, `buscarMetadadosEstoque` em lote e `getReferenceById`).

### 2.1 Published Language — `inv.inventory.api` (R9: só `java..`, `common..`, `inv..api..`)

```java
package inv.inventory.api;

import java.util.Objects;

/**
 * Open Host Service de comandos de estoque para o Checkout (protocolo Try-Confirm-Cancel).
 *
 * <p><b>Contrato transacional:</b> todas as operações exigem uma transação ativa
 * ({@code Propagation.MANDATORY}) e participam do mesmo commit/rollback do chamador (ADR-0002).
 *
 * <p><b>Contrato de concorrência:</b> a implementação processa os itens em ordem crescente de
 * {@code produtoId}, independente da ordem recebida, e executa um UPDATE atômico por item.
 * Isso garante uma ordem global de aquisição de row locks (prevenção de deadlock — ADR-0002, adendo).
 *
 * <p><b>Falhas:</b> {@code common.exception.BusinessException} com a mensagem do primeiro item
 * (em ordem de {@code produtoId}) que violar a pré-condição. O chamador deve deixar a transação reverter.
 */
public interface EstoqueCommandService {

    /** Try: move saldo de disponível para reservado e registra movimentação RESERVA. */
    void reservar(ComandoEstoqueVenda comando);

    /** Confirm: consome o saldo reservado (baixa definitiva) e registra movimentação SAIDA. */
    void confirmarBaixa(ComandoEstoqueVenda comando);

    /** Cancel: devolve o saldo reservado ao disponível e registra movimentação CANCELAMENTO_RESERVA. */
    void estornarReserva(ComandoEstoqueVenda comando);
}
```

```java
package inv.inventory.api;

import java.math.BigDecimal;
import java.util.List;
import java.util.Objects;

/**
 * Comando imutável de estoque vinculado a uma venda.
 * Lista vazia é permitida e resulta em no-op (paridade com o laço atual sobre uma coleção vazia).
 * Itens duplicados NÃO são consolidados (paridade — Q9).

public record ComandoEstoqueVenda(long vendaId, List<ItemComando> itens) {
    public ComandoEstoqueVenda {
        if (vendaId <= 0) throw new IllegalArgumentException("vendaId deve ser positivo");
        Objects.requireNonNull(itens, "itens");
        itens = List.copyOf(itens);               // cópia defensiva imutável; rejeita elementos nulos
    }
}

    public ItemComando {
        if (produtoId <= 0) throw new IllegalArgumentException("produtoId deve ser positivo");
        Objects.requireNonNull(quantidade, "quantidade");
        if (quantidade.signum() <= 0) throw new IllegalArgumentException("quantidade deve ser positiva");
    }
}
```

```java
package inv.inventory.infrastructure.query;

@Component
@Transactional(readOnly = true)
class JpaCatalogoQueryService implements CatalogoQueryService {   // package-private (R10/R14)

    private final ProdutoRepository produtoRepository;

    JpaCatalogoQueryService(ProdutoRepository produtoRepository) {
        this.produtoRepository = Objects.requireNonNull(produtoRepository, "produtoRepository");
    }

    @Override
    public List<ProdutoCheckoutView> buscarParaCheckout(Set<Long> produtoIds) {
        Objects.requireNonNull(produtoIds, "produtoIds");
        if (produtoIds.isEmpty()) return List.of();
        return produtoRepository.buscarViewsCheckout(produtoIds);
    }
}
```

> [!NOTE]
> Quando chamado de dentro de `iniciarVenda` (transação read-write), o `@Transactional(readOnly = true)` **participa** da transação existente (propagação `REQUIRED`): o flag `readOnly` não é reaplicado à transação em curso, então não há efeito colateral no flush. Fora de transação, abre uma transação somente leitura, como os demais query services.

### 2.3 Inventory — comandos: `EstoqueService` package-private implementando a API

Solução exata para os três usos da entidade `Produto` (F6):

| Necessidade | Antes | Depois | Custo |
|---|---|---|---|
| `saldoAnterior` para o anti-spam | `produto.getEstoqueDisponivel()` lido **antes** do lock (obsoleto sob concorrência) | `novoSaldo.add(quantidade)`: pré-imagem **exata** derivada do `RETURNING`, sob o row lock | 0 query |
| `estoqueMinimo` / `nome` | Entidade carregada pelo Checkout (`findAllById`) | `buscarMetadadosEstoque(ids)` em lote, só na **reserva**; em baixa/estorno, só no **caminho de erro** | +1 `SELECT` por reserva (PK, ~sub-ms); 0 no caminho feliz de baixa/estorno |
| `MovimentacaoEstoque.produto` | `mov.setProduto(produto)` | `mov.setProduto(produtoRepository.getReferenceById(id))` (proxy, insere só o FK) | 0 query |

> [!IMPORTANT]
> **Por que a pré-imagem calculada é imune a race conditions:** o `UPDATE produtos SET estoque_disponivel = estoque_disponivel - :qtd ... RETURNING estoque_disponivel` adquire o row lock e lê a versão mais recente da linha (re-check do `READ COMMITTED`). Portanto `RETURNING + qtd` é exatamente o saldo **imediatamente anterior a esta transação**, serializado pelo lock. Com isso, cada transição `> mínimo → ≤ mínimo` é observada por **exatamente uma** transação. O código atual, com leitura pré-lock, pode emitir N alertas quando N caixas cruzam o limiar ao mesmo tempo. O metadado `estoqueMinimo` é lido sem lock, o que é aceitável: é dado cadastral, não saldo contendido.

```java
package inv.inventory.usecase;

import common.exception.BusinessException;
import common.exception.ResourceNotFoundException;
import inv.inventory.api.ComandoEstoqueVenda;
import inv.inventory.api.EstoqueCommandService;
import inv.inventory.api.ItemComando;
import inv.inventory.domain.model.MovimentacaoEstoque;
import inv.inventory.domain.model.TipoMovimentacao;
import inv.inventory.infrastructure.messaging.EstoqueAtingiuMinimoEvent;
import inv.inventory.infrastructure.messaging.EstoqueBaixoMessage;
import inv.inventory.infrastructure.persistence.MovimentacaoRepository;
import inv.inventory.infrastructure.persistence.ProdutoMetadadosEstoque;
import inv.inventory.infrastructure.persistence.ProdutoRepository;
import org.springframework.context.ApplicationEventPublisher;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Propagation;
import org.springframework.transaction.annotation.Transactional;

import java.math.BigDecimal;
import java.time.LocalDateTime;
import java.util.*;
import java.util.function.Function;
import java.util.stream.Collectors;

@Service
class EstoqueService implements EstoqueCommandService {   // package-private a partir da E3 (R14)

    /** Ordem global de aquisição de row locks em `produtos` (ADR-0002, adendo DEBT-ARCH-002 / F5). */
    static final Comparator<ItemComando> ORDEM_DE_LOCK = Comparator.comparingLong(ItemComando::produtoId);

    private final ProdutoRepository produtoRepository;
    private final MovimentacaoRepository movimentacaoRepository;
    private final ApplicationEventPublisher eventPublisher;

    EstoqueService(ProdutoRepository produtoRepository,
                   MovimentacaoRepository movimentacaoRepository,
                   ApplicationEventPublisher eventPublisher) {
        this.produtoRepository = produtoRepository;
        this.movimentacaoRepository = movimentacaoRepository;
        this.eventPublisher = eventPublisher;
    }

    @Override
    @Transactional(propagation = Propagation.MANDATORY)
    public void reservar(ComandoEstoqueVenda comando) {
        if (comando.itens().isEmpty()) return;
        Map<Long, ProdutoMetadadosEstoque> metadados = carregarMetadados(comando);

        for (ItemComando item : emOrdemDeLock(comando)) {
            ProdutoMetadadosEstoque meta = exigir(metadados, item.produtoId());
            BigDecimal novoSaldo = produtoRepository.reservarEstoqueAtomo(item.produtoId(), item.quantidade());
            if (novoSaldo == null) {
                throw new BusinessException("Estoque insuficiente para o produto: " + meta.nome());   // mensagem idêntica (Q9)
            }
            BigDecimal saldoAnterior = novoSaldo.add(item.quantidade());   // pré-imagem exata sob row lock (F6)
            verificarEAlertarEstoqueBaixo(meta, saldoAnterior, novoSaldo);
            registrarMovimentacao(item.produtoId(), item.quantidade(), TipoMovimentacao.RESERVA,
                    "Reserva de estoque para Venda #" + comando.vendaId(), comando.vendaId());
        }
    }

    @Override
    @Transactional(propagation = Propagation.MANDATORY)
    public void confirmarBaixa(ComandoEstoqueVenda comando) {
        for (ItemComando item : emOrdemDeLock(comando)) {
            if (produtoRepository.confirmarBaixaEstoqueAtomo(item.produtoId(), item.quantidade()) == null) {
                throw new BusinessException("Inconsistência: Tentativa de baixar mais estoque reservado do que o existente para: "
                        + nomeDoProduto(item.produtoId()));
            }
            registrarMovimentacao(item.produtoId(), item.quantidade(), TipoMovimentacao.SAIDA,
                    "Baixa definitiva da Venda #" + comando.vendaId(), comando.vendaId());
        }
    }

    @Override
    @Transactional(propagation = Propagation.MANDATORY)
    public void estornarReserva(ComandoEstoqueVenda comando) {
        for (ItemComando item : emOrdemDeLock(comando)) {
            if (produtoRepository.estornarReservaEstoqueAtomo(item.produtoId(), item.quantidade()) == null) {
                throw new BusinessException("Inconsistência: Tentativa de cancelar reserva inexistente para: "
                        + nomeDoProduto(item.produtoId()));
            }
            registrarMovimentacao(item.produtoId(), item.quantidade(), TipoMovimentacao.CANCELAMENTO_RESERVA,
                    "Estorno de reserva. Venda #" + comando.vendaId(), comando.vendaId());
        }
    }

    /** Stream.sorted em fonte ordenada é estável: duplicados do mesmo produto mantêm a ordem relativa. */
    private static List<ItemComando> emOrdemDeLock(ComandoEstoqueVenda comando) {
        return comando.itens().stream().sorted(ORDEM_DE_LOCK).toList();
    }

    private Map<Long, ProdutoMetadadosEstoque> carregarMetadados(ComandoEstoqueVenda comando) {
        Set<Long> ids = comando.itens().stream().map(ItemComando::produtoId).collect(Collectors.toSet());
        return produtoRepository.buscarMetadadosEstoque(ids).stream()
                .collect(Collectors.toMap(ProdutoMetadadosEstoque::id, Function.identity()));
    }

    private static ProdutoMetadadosEstoque exigir(Map<Long, ProdutoMetadadosEstoque> metadados, long produtoId) {
        ProdutoMetadadosEstoque meta = metadados.get(produtoId);
        if (meta == null) {   // defensivo: o Checkout já valida existência via CatalogoQueryService
            throw new ResourceNotFoundException("Produto não encontrado: " + produtoId);
        }
        return meta;
    }

    /** Só no caminho de erro: o UPDATE com 0 linhas não aborta a transação no PostgreSQL. */
    private String nomeDoProduto(long produtoId) {
        return produtoRepository.buscarMetadadosEstoque(List.of(produtoId)).stream()
                .findFirst().map(ProdutoMetadadosEstoque::nome).orElse("#" + produtoId);
    }

    private void registrarMovimentacao(long produtoId, BigDecimal quantidade, TipoMovimentacao tipo, String observacao, long vendaId) {
        MovimentacaoEstoque mov = new MovimentacaoEstoque();
        mov.setProduto(produtoRepository.getReferenceById(produtoId));   // proxy: 0 SELECT
        mov.setQuantidade(quantidade);
        mov.setTipo(tipo);
        mov.setDataHora(LocalDateTime.now());
        mov.setObservacao(observacao);
        mov.setVendaId(vendaId);
        movimentacaoRepository.save(mov);
    }

    private void verificarEAlertarEstoqueBaixo(ProdutoMetadadosEstoque meta, BigDecimal antes, BigDecimal depois) {
        BigDecimal minimo = meta.estoqueMinimo();
        if (minimo != null && antes.compareTo(minimo) > 0 && depois.compareTo(minimo) <= 0) {
            eventPublisher.publishEvent(new EstoqueAtingiuMinimoEvent(
                    new EstoqueBaixoMessage(1, UUID.randomUUID().toString(), meta.nome(), depois, minimo)));
        }
    }
}
```

> [!TIP]
> **Alternativa avaliada e adiada:** enriquecer os `RETURNING` das três queries atômicas (`RETURNING estoque_disponivel, estoque_minimo, nome`) eliminaria o `SELECT` de metadados da reserva. Foi adiada porque muda as assinaturas das queries normativas da ADR-0002 e depende do mapeamento de projeção em query nativa de modificação. O ganho (~1 round-trip indexado por venda) não justifica o risco nesta etapa.

**Transição aditiva (E2 → E3):** na E2, `EstoqueService` continua `public`, passa a `implements EstoqueCommandService` e **mantém** os três métodos legados `(Produto, BigDecimal, Long)` marcados com `@Deprecated(forRemoval = true)`, sem alteração de corpo. Na E3, depois que os consumidores migrarem, os métodos legados são apagados e a classe/construtor viram package-private. `inv.service.EstoqueServiceTest` é movido (`git mv`) para `inv.inventory.usecase` (mesmo pacote, exigência da visibilidade).
